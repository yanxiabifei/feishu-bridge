# 常见问题

> 绝大多数"没反应"都出在飞书应用配置，而不是代码。先跑 `npm run setup`——它会一步步自检，卡在第几步就对应看第几节。

## 安装与启动

### `npm start` 报「缺少飞书凭据：先运行 npm run setup」

还没有初始化，或者 `state/config.json` 被删了。跑：

```bash
npm run setup
```

### 控制台没输出，进程直接退出

大概率是已经在运行了。守护进程是单例，重复启动只会在日志里写一行 `daemon.already_running` 然后退出。看 `logs/`，或者在私聊里给机器人发「列表」确认它还活着。

### `npm test` 报找不到测试文件

Node.js 版本太低。测试脚本依赖 `node --test` 的 glob 展开，需要 **Node 22 或 24**。`node -v` 确认一下。

### 能不能开机自启

```bash
npm run autostart            # 等价于 node scripts/autostart.js install
node scripts/autostart.js status
node scripts/autostart.js uninstall
```

它注册一个名为 `FeishuBridge.Daemon` 的 Windows 计划任务，登录后延迟 15 秒启动，失败会隔 60 秒重试。

## 飞书侧：配好了但没反应

### `npm run setup` 卡在「长连接收到消息」

自检在等你**用手机私聊机器人**发一句话。如果发了还是超时，逐项核对：

1. 事件订阅里有 `im.message.receive_v1`；
2. 这个事件的**连接方式选的是「长连接」**，不是「将事件发送至开发者服务器」；
3. 应用**已创建版本并发布**，不是停在草稿；
4. 你自己在应用的**可用范围**里（自建应用常见坑：只加了部门没加人）；
5. App ID / App Secret 是最新的（重置过 Secret 要重新 `npm run setup`）。

### 自检卡在「换取 tenant_access_token」

App ID / Secret 不对，或者应用被停用。去开放平台后台重新复制一次。

### 自检报权限不足

按 README 里的表核对权限：`im:message`、`im:message:send_as_bot`、`im:chat`、`im:chat:delete`、`cardkit:card`。加完权限**要重新发版**才生效。

### 群里 @机器人 没反应，私聊正常

机器人不在这个群里，或者群里 @ 的不是它。私聊发「列表」看不到这个群，就说明群还没绑定会话——在群里发第一条带别名的消息即可创建。

### 回复卡片一直显示「处理中」

说明消息收到了、agent 起来了，但没等到结束。依次检查：

1. `claude --version` 在你启动守护进程的那个终端里能跑吗？（PATH 是启动时继承的）
2. 别名对应的目录还在吗？
3. `logs/` 里最近一条错误是什么？

### 能看到文字回复，但卡片按钮/「当前画面」不可用

卡片通道（`cardkit:card`）权限没开。文字回复不受影响。

## 使用中

### 一个群能绑定多个项目吗

不能。一个群 ↔ 一个会话 ↔ 一个目录，这是刻意的设计，避免串话。要多项目就多拉几个群。

### 能接管我已经开着的 Claude Code 窗口吗

不能。桥只会新起进程，两边并行、互不干扰。

### 电脑睡眠/关机后会怎样

手机唤不醒电脑。守护进程跟着系统睡眠一起停，醒来后飞书长连接会自动重连。

### 怎么彻底卸载

```bash
node scripts/autostart.js uninstall   # 如果装过自启
# 然后在飞书开放平台停用/删除这个自建应用
```

再删掉项目目录即可。`state/` 里有加密后的 App Secret，跟着目录一起删。

## 日志与隐私

### 日志在哪

项目目录下的 `logs/`（已被 `.gitignore` 排除）。

### 日志里会有我的命令内容吗

会。日志用于排障，可能包含消息正文、目录名、工具调用摘要。**贴到 issue 之前先删私人信息**，并跑一遍：

```bash
npm run check:logs
```

它按 key 名和已知凭据形态扫描，能挡住大部分误贴 token 的情况，但不能替代人工检查。

### 消息会不会经过第三方服务器

不会。出站只走飞书开放平台的 Open API，入站是飞书的长连接。没有公网 IP、没有内网穿透、没有中转服务。但请注意：**飞书本身能看到消息内容**，这是它的产品链路。
